11 //! \brief A DPP module to delete events from a pipeline
12 /*!
13  * Filtering events using Falaise's @ref falaise::processing::filter module creates
14  * branches in the processing pipeline, the choice of which branch to take being determined
15  * by the filter. In some use cases, only one branch may be relevant to further processing,
16  * the other simply representing a "dead end" (e.g. "fails cut"). `black_hole_module` implements
17  * this use case, discarding any events it is passed from further processing and output to file.
18  * For example, in the pipeline script:
19  *
20  * ```ini
21  * [name="pipeline", type="MyFilter"]
22  * on_accept : string = "FurtherProcessing"
23  * on_reject : string = "BlackHole"
24  * ... filter config ...
25  *
26  * [name="FurtherProcessing", type="FurtherProcessing"]
27  * ...
28  *
29  * [name="BlackHole", type="falaise::processing::black_hole_module"]
30  * ...
31  * ```
32  *
33  * events accepted by the `MyFilter` filter would flow to the `FurtherProcessing` module and
34  * eventually to the main output file. Rejected events flow to the `black_hole_module` and
35  * are removed from the pipeline and hence output to file.
36  *
37  * one path of which events will flow
38  * \sa falaise::processing::filter
39  * \sa falaise::processing::module
40  */
