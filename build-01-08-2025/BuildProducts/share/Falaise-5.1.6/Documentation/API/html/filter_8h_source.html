19 //! \brief A DPP module wrapping a simple filtering algorithm
20 /*!
21  * An extension of @ref falaise::processing::module to implement filtering of events.
22  *
23  * Whereas @ref falaise::processing::module is intended to wrap algorithms that read and
24  * write data to events ("producer"), `filter` wraps algorithms that only read the data
25  * in the event and make an if/else decision on how to proceed with further processing.
26  * Each branch of this decision forwards the event to a module/filter to handle onward
27  * processing.
28  *
29  * This class template templates the handling of the input and if/else output modules
30  * for a type `T` that implements the `filter` concept. This type only needs to implement
31  * constructors for initialization (via configuration properties) and a `filter` member function
32  * returning a boolean indicating the if/else decision.
33  *
34  * The type to be wrapped must meet the requirements:
35  *
36  * - `DefaultConstructible`
37  * - `Construtible` with `T(falaise::property_set const&, datatools::service_manager&)
38  * - `CopyAssignable`
39  * - Has a member function with signature
40  * ```cpp
41  * bool filter(const datatools::things& d)
42  * ```
43  *
44  * For example:
45  *
46  * ```cpp
47  * class MyFilter
48  * {
49  * MyFilter(); // ideally this is =default
50  * MyFilter(falaise::property_set const& config, datatools::service_manager& services);
51  *
52  * bool process(const datatools::things& data);
53  * };
54  * ```
55  *
56  * The user defined constructor must throw if initialization fails.
57  *
58  * The class is wrapped and registered with Falaise's pipeline plugin system
59  * by calling the macro #FALAISE_REGISTER_FILTER(T)
60  * in the filters's implementation file, e.g.
61  *
62  * ```cpp
63  * // This is MyFilter.cpp
64  * #include "falaise/snemo/processing/filter.h"
65  * class MyFilter
66  * {
67  * ... as above ...
68  * };
69  *
70  * FALAISE_REGISTER_FILTER(MyFilter)
71  * ```
72  *
73  * The module will be registered with a string key equal to the typename
74  * so that use as a module in pipeline scripts is transparent, e.g.
75  *
76  * ```ini
77  * [name="theLabel" type="MyFilter"]
78  * ... config ...
79  * ```
80  *
81  * The filter `process` member function must return `true` if the supplied
82  * event passes the filter, and `false` otherwise. Onward processing of the
83  * event can be selected through the module level `on_accept` and `on_reject`
84  * string parameters:
85  *
86  * ```ini
87  * [name="theLabel", type="MyFilter"]
88  * on_accept : string = "A"
89  * on_reject : string = "B"
90  * ... filter config ...
91  *
92  * [name="A", type="AlgoA"]
93  * ...
94  *
95  * [name="B", type="AlgoB"]
96  * ...
97  * ```
98  *
99  * where these parameters must be valid names of other modules in the
100  * configuration. There is no limit on the type of module here, so chains
101  * of processing and filtering modules can be built up. Note however that
102  * whilst recursion/iteration is permitted, it is not yet recommended and may lead
103  * to infinite loops.
104  *
105  * \sa falaise::processing::module
106  * \sa dpp::base_module
107  */
